# 0025. Evaluate Wiki Generation by Block Windows

## Status
Proposed

## Context
document-svc가 PDF 변환 결과를 64KiB 파트 대신 문서 하나(최대 5MB)로 인제스트하도록 바뀐다([document ADR-0024](https://github.com/FruitionKR/Fruition-document/blob/main/docs/adr/0024-converted-pdf-single-document.md)). 의미 추출은 7,000자 패킷으로 나뉘지만, Wiki 생성 평가(`evaluate_generation`)는 원문 블록 전체와 정규화 결과 전체를 요청 하나에 넣는다.

1MB 문서(블록 3,896개, 패킷 172개)로 측정하니 평가 입력이 약 290만 자였고, Gemini 입력 한도(1,048,576 토큰)를 넘어 인제스트가 실패했다. 같은 측정에서 개념 해석·개념 갱신 판정(후보 311개)과 클러스터 판정(후보 231개, 50초)은 통과했다.

## Decision
- 원문 블록 합계가 120,000자 이하면 지금처럼 요청 하나로 평가한다.
- 넘으면 연속된 블록을 120,000자 단위 구간으로 나눈다. 구간마다 그 구간의 블록(`block_id` 또는 `source_reference_id`)을 근거로 가리키는 정규화 항목만 넣는다. 근거가 없는 항목은 첫 구간에 넣는다.
- 구간은 최대 4개를 동시에 평가한다.
- 결과 병합: `passed`는 모든 구간 통과, `retry_recommended`는 한 구간이라도 권고하면 참, `issues`·`warnings`·`retry_feedback`은 이어 붙이고, `scores`는 구간의 블록 수로 가중 평균한다.
- 결정적 가드(`apply_generation_evaluation_guards`)는 병합 결과에 문서 전체 기준으로 한 번 적용한다.

## Alternatives
- **문서를 다시 64KiB 파트로 나눠 인제스트:** 문서 하나가 여러 위키 소스로 흩어져 그래프가 쪼개진다.
- **평가 입력에서 원문 블록을 빼기:** 근거 충실도를 원문과 대조할 수 없게 된다.
- **패킷 단위로 평가:** 1MB 문서에서 172번 호출해야 하고, 개념처럼 여러 패킷에 걸친 항목을 판단할 맥락이 너무 좁다.

## Consequences
- 1MB 문서 인제스트가 끝까지 통과한다(측정 1,137초, 평가 권고로 재추출 1회 포함).
- 여러 구간에 걸친 항목은 구간마다 중복해서 평가된다. 1MB 문서의 구간 입력 합계는 약 437만 자로, 하나로 보낼 때보다 늘어난다.
- 구간 사이의 일관성(같은 개념을 구간마다 다르게 판단하는 경우)은 LLM이 보지 못한다. 결정적 가드가 문서 전체 기준으로 보완한다.
- 클러스터 판정은 후보 전체를 요청 하나로 보낸다. 5MB 문서는 후보가 약 1,000개로 늘어 180초 제한에 걸릴 수 있으며, 후보 좁히기 작업에서 함께 다룬다.
