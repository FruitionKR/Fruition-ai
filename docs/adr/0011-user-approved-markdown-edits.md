# 0011. Apply Markdown Agent Edits Only after User Approval

## Status
Implemented

## Context
LLM이 생성한 Markdown은 사용자의 의도와 다르거나 원문 구조를 손상할 수 있다. 생성 직후 원본 문서에 저장하면 사용자가 변경 내용을 확인하거나 거부할 기회가 없다.

## Decision
Markdown Agent는 문서를 직접 저장하지 않고 적용 가능한 edit proposal을 반환하며, 사용자가 preview와 diff를 확인하고 수락한 경우에만 문서에 반영한다.

기존 문서 편집은 공통 `ChatCompletionsMarkdownEditor`에서 코드 검증 후 별도 LLM 호출로 요청 의도, 명시한 제약, 의미·근거 보존을 평가한다. 일반 Markdown 교체와 source range 편집에 모두 적용하며, 새 문서 생성과 Agent 도구 실행 검증은 이 평가의 대상이 아니다. 평가자는 사용자 선택 모델과 기존 호출·추적 경로를 사용한다.

통과하면 즉시 편집안을 반환한다. 코드 검증 또는 LLM 평가에 실패하면 실패 사유와 이전 출력을 전달해 한 번만 재생성한다(최초 생성 포함 최대 2회). 두 번째에도 실패하거나 평가 응답 형식이 잘못되면 편집안을 반환하지 않는다. 평가 API 장애 역시 통과로 취급하지 않는다. 평가는 사용자 승인을 대체하지 않는다.

평가자에게 생성용 JSON 스키마를 전달하지 않는다. 편집된 문장과 사용자 제약을 평가하도록 역할을 분리하며, 실제 줄 배열을 함께 전달해 문자열의 `\\n`과 줄바꿈을 구별한다. Source range 재시도에는 조립된 이전 결과도 전달하고, 고정 문구를 구간 안에 중복 삽입하지 않도록 안내한다. 제목 추가와 서식 변경을 함께 요청한 경우에는 원문 각 줄을 그대로 유지해야 하는 ‘추가만 수행’ 규칙을 적용하지 않는다.

## Alternatives Considered
- Agent 결과를 원본 문서에 즉시 저장: 잘못된 변경을 사용자가 확인하기 전에 반영하므로 기각했다.
- 수정된 전체 문서만 반환: 변경 범위와 적용 여부를 명시하기 어려워 target을 포함한 edit operation을 선택했다.

## Consequences/Tradeoffs
### Positive
- 사용자가 변경 범위와 결과를 확인하고 적용·취소·재생성을 선택할 수 있다.
- Agent 생성과 실제 문서 저장의 책임을 분리할 수 있다.

### Negative
- 코드 검증을 통과한 시도마다 LLM 호출이 한 번 추가되어 비용과 응답 시간이 늘어난다. 같은 모델의 평가는 오류를 함께 놓칠 수 있으며, 실제 품질 향상은 별도 고정 입력 평가로 측정해야 한다.
- preview, diff와 적용 상태를 Frontend가 관리해야 한다.
- 제안 생성 이후 문서가 바뀌면 적용 전에 version 충돌을 확인해야 한다.

## 검증

원본 [local-pilot PR #264](https://github.com/FruitionKR/local-pilot/pull/264)에서 측정한 결과다. 기준 커밋 `0c46c9de`는 원본 저장소의 커밋이며 이 저장소의 이력이 아니다.

고정 19종 요청에서 수집한 최초 초안 114개를 세 버전에 동일하게 재생했다. 생성·런타임 평가는 `gpt-5-nano`(medium), 별도 블라인드 평가는 `gemini-3.1-flash-lite`를 사용했다. 별도 평가자는 사전 정답을 붙인 정상·오류 사례 12/12건을 맞혔다. 미반환도 실패로 세고, 기존 코드 검사와 별도 모델 평가를 모두 통과해야 성공으로 집계했다.

| 비교 버전 | 통과 | 비율 | 환산 평균 시간 | 논리 LLM 호출 수 |
| --- | ---: | ---: | ---: | ---: |
| 기준 커밋 `0c46c9de` | 94/114 | 82.5% | 11.11초 | 121 |
| 코드·재시도 안내 수정, 평가자 제외 | 98/114 | 86.0% | 9.39초 | 115 |
| 평가자 포함 최종 구현 | 104/114 | 91.2% | 18.92초 | 251 |

최종 구현은 기준 대비 10건(+8.8%p), 평가자 제외 대조군 대비 6건(+5.3%p)을 개선했다. 이 비교에서 기존 통과가 실패로 바뀐 사례는 없었다. 의미·문장 평가만 보면 95 → 99 → 104건이며, 코드 검사만 보면 110 → 113 → 111건이다. 코드 점수 하나만으로는 어색한 문장과 누락을 구별하지 못하므로 두 기준을 함께 사용한다.

시간은 기록된 최초 생성 시간에 이후 실모델 호출 시간을 합산한 값이며 서비스 전체의 실측 지연이 아니다. 호출 수에는 재생한 최초 호출도 포함되며 청구 금액을 뜻하지 않는다. 실패 초안을 재사용한 개발 회귀셋이므로 독립 테스트셋·배포 사용자 정확도로 일반화하지 않는다. 별도 모델에도 판정 오류가 있을 수 있다. 최종 구현에서도 3건은 반환을 차단했고, 반환한 111건 중 7건은 별도 평가를 통과하지 못했다. 다른 생성 모델의 품질은 이번 비교로 검증하지 않았다.
