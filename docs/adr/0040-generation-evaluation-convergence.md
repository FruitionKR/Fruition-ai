# 0040. 편입 평가는 높음 심각도만 막고 이전 요청을 이어 본다

## 맥락
Jev 평가 워크스페이스(2026-10-30, Haiku 편입, 추출 최대 2회·평가 최대 3회)에서 11개 문서 중 5개가 끝까지 불합격(`unresolved`)이었다.

- 평가자 계약이 "문제가 하나라도 있으면 불합격"이라, 중간·낮음 심각도 문제만으로도 재시도했다. 한 문서(쿠버네티스 디플로이먼트)는 세 번의 평가 모두 합격 점수를 넘고 높음 문제도 없었는데 불합격했다.
- 평가자는 시도마다 이전 판단을 모른 채 다시 평가해, 같은 대상에 반대 요청을 냈다. 예: 같은 개념에 내려라 → 합쳐라 → 내려라 → 쪼개라, 다른 개념에 합쳐라 → 쪼개라 → 합쳐라.
- 재추출은 직전 피드백만 받아 앞서 고친 것을 되돌렸고, 같은 요청이 네 번 연속 나온 개념도 있었다.

## 결정
- 평가자는 수정해야 받아들일 수 있는 높음 심각도 문제만 `issues`에 넣고, 중간·낮음 문제는 `warnings`에 넣는다. 근거 없음·잘못된 근거, 근거 없는 핵심 개념, 깨진 관찰, 빠진 원문 내용이 높음 문제다.
- 코드(`evaluate_generation`)는 평가자가 `issues`에 넣은 중간·낮음 문제를 경고로 옮긴다. 옮긴 뒤 남은 문제가 없으면 평가자 프롬프트의 합격 점수(`PASS_SCORE_THRESHOLDS`)로 다시 판정한다. 심각도가 없는 문제는 막는 문제로 본다.
- 평가 입력에 앞선 시도의 요청(`previous_requests`: 시도·유형·대상·피드백)을 넣는다. 평가자는 원문이 직접 반박하지 않는 한 같은 대상에 반대 요청을 내지 않고, 이미 반영된 요청을 다시 내지 않는다.
- 재추출 프롬프트에 마지막 피드백과 함께 앞선 시도의 요청을 "유지할 수정"으로 넣는다.

## 대안과 기각 사유
- **문제 유형별로 막을지 정하기:** 같은 유형도 대상에 따라 심각도가 달라, 평가자가 매기는 심각도를 따른다.
- **시도 횟수만 늘리기:** 피드백이 엇갈리는 동안은 시도를 늘려도 수렴하지 않는다.
- **평가자 판정 대신 점수만 보기:** 근거 없음처럼 점수에 잘 드러나지 않는 높음 문제를 놓친다.

## 결과
- 중간·낮음 문제만 남은 결과는 점수 기준을 넘으면 합격한다. 남은 문제는 `warnings`로 결과에 남는다.
- 평가 입력과 재추출 프롬프트가 앞선 요청만큼 길어진다(시도당 문제 수십 개 수준).
- 코드 검증(`evaluation_guards`)이 붙이는 문제는 이 규칙과 별개로 그대로 막는다.
