# 0042. 개념 페이지는 하위 항목을 모아 두는 대분류로 만들고, 두꺼워진 하위 항목은 자식 페이지로 분리한다

## Status
Proposed

## Context
- **개념 크기가 모델 판단에 달려 있다.** 편입 추출 모델이 정하는 개념 크기가 곧 개념 페이지 크기다. 같은 Kubernetes 문서를 넣었는데도 이름에 Deployment·kubectl이 들어간 개념 페이지 수가 워크스페이스마다 2~17개로 달랐다(로컬 평가 워크스페이스 10곳, 2026-11-01).
  - 최근 워크스페이스에는 `Deployment Rollout`, `Deployment Rollback`, `Deployment Conditions`, `Label Selector (Deployment)`, `kubectl scale`, `kubectl rollout history`, `디플로이먼트 재생성`이 각각 개념 페이지로 생겼다. 모두 Deployment 페이지 안의 항목이면 충분한 크기다.
  - 개념 판정(ADR-0038)은 같은 개념을 합치고 직접 관계만 잇는다. "B가 A에 딸린 세부 내용"이라는 판정은 없다. 그래서 세부 항목은 별도 개념으로 남거나 링크로 이어질 뿐이다.
- **lint가 구조가 아니라 링크를 덧붙인다.** lint 승격(ADR-0037)은 근거 문서 2개 이상인 클러스터를 개념 페이지로 만들고 기존 개념과 쌍 판정해 링크를 잇는다. 11개 문서 평가에서 관계 후보가 44개 올라왔고, 일부 승격 페이지는 문서 연결(`document_wiki_links`)이 없었다. 잘게 쪼개진 개념을 링크로 보완할수록 그래프가 엉킨다.
- **크게 잡기만 하면 RAG 문제가 돌아온다.** 개념 페이지가 커지면 페이지 하나가 큰 청크가 되어 검색과 근거 선택의 정밀도가 떨어진다.
- **기존 저장·복원 구조.** 개념 페이지는 작업마다 남긴 기여 기록(`wiki/{workspace_id}/pages/{page_id}/ops/{operation_id}.json`)을 순서대로 재생해 만든다(`concept_contribution_rebuild.py`). 링크도 기록의 추가·삭제를 재생해 정한다(`replay_supported_links`). 편입·lint 복원은 취소한 작업의 기록을 빼고 재생한다. 고아 간선은 끝 페이지가 지워졌거나(`endpoint_deleted`) 재생한 기록에 근거가 없는(`no_active_support`) 링크다. 재생은 한 페이지의 생성 기록이 모두 같은 slug라고 가정한다.

## Decision
위키백과의 요약식 문서(Summary style)와 B-tree 노드 분할을 따른다. 내용은 모이면 올라가고 두꺼워지면 쪼개진다. 크기는 모델의 감각이 아니라 **모인 개수와 근거량**으로 정한다.

1. **하위 항목을 데이터로 둔다.**
   - 개념 페이지는 하위 항목(sub-entry) 목록을 가진다. 하위 항목은 워크스페이스 안에서 고정 id, 이름, 근거, 상위 항목(`parent_entry_id`, 없으면 페이지 바로 아래)을 가진다.
   - 본문의 하위 항목 목록(인덱스)은 이 데이터로 그린다. 중첩 목록으로 렌더링한다.
   - 하위 항목의 추가·이동·삭제는 기여 기록에 id로 남긴다. 페이지와 하위 항목은 모두 기록 재생으로 만든다.
2. **하위 항목의 집은 하나, 다른 페이지에는 참조만 둔다.**
   - 하위 항목은 한 페이지(집)에만 속한다. 다른 페이지에 같은 것이 나오면 내용을 복사하지 않고 그 항목을 가리키는 참조 항목을 둔다.
   - 소유 관계는 트리다. 참조는 링크로 저장해 고아 간선 규칙을 그대로 따른다.
3. **편입: 세부 항목을 뽑고, 상위 항목에 배정하고, 개수로 승격한다.**
   - 추출은 지금처럼 세부 항목까지 뽑는다. 잘게 뽑혀도 된다.
   - 배정: 세부 항목마다 이번 문서의 핵심 항목 중 어디에 딸리는지 정한다. 이름이 상위 항목 이름으로 시작하거나 그 이름을 수식어로 가지면 판정 없이 배정한다. 나머지는 같음·관련 판정과 따로 묻는 Jev 쌍 판정 `part_of` / `not_part_of`(B는 A에 딸린 세부 내용인가)로 묻는다. P(part_of)가 `PART_OF_MIN_PROBABILITY`(초기값 0.9) 미만이거나 Jev를 쓸 수 없으면 배정하지 않는다. 정의·근거가 없는 항목은 묻지 않는다.
   - 같은 것 찾기: 새 세부 항목은 워크스페이스의 기존 하위 항목에서 이름·임베딩 상위 후보 몇 개만 골라 쌍 판정한다. `same`이면 기존 항목에 근거를 더하고 이번 부모에는 참조를 둔다. 맥락이 다르면(같은 이름의 다른 동작·설정) 이번 부모 아래 새 항목으로 둔다. **애매하면 따로 둔다.** 다른 것을 같은 것으로 합치는 오류가 반대 오류보다 해롭고, 따로 둔 중복은 lint 재검사로 고칠 수 있다.
   - 승격: 세부 항목이 `K`개 이상 배정된 항목만 개념 페이지가 된다. 모자라면 가장 가까운 상위 페이지의 하위 항목으로 들어간다.
   - 판정은 ADR-0033대로 편입 반영 단계(워크스페이스 개념 잠금 안)에서 한다.
4. **lint: 바뀐 페이지만 재검사하고, 분리·이동·합치기를 한다.**
   - 이번에 하위 항목이 바뀐 페이지에 변경 표시를 하고, lint는 그 페이지만 본다. 판정 범위는 그 페이지의 하위 항목이다. 비용은 워크스페이스 크기가 아니라 변경량에 비례한다.
   - 이동: 잘못 배정된 하위 항목을 다른 상위 항목으로 옮긴다. 하위의 하위가 맞으면 그 아래로 넣는다.
   - 합치기: 같은 내용의 하위 항목을 하나로 합친다.
   - 분리: 하위 항목의 자식이 `C`개(초기값 5) 이상이거나 근거가 `E`개(초기값 10) 이상이면 자식 페이지로 분리한다. 근거 원문 문서 수는 기준으로 쓰지 않는다. 두 문서에 한 번씩만 나온 항목까지 분리돼 두꺼워지면 쪼갠다는 취지와 맞지 않는다. 부모에는 요약과 자식 페이지 링크를 남긴다. 상위 항목 값만 바꾸므로 그 아래 자식들은 함께 내려간다. 분리 규칙이 있어 한 페이지 안의 하위 항목 깊이는 2단계 정도에서 멈추고, 깊어지는 것은 페이지 트리다.
   - 다시 합치기: 자식 페이지가 줄어 자식 `C_low`개(초기값 2) 이하이고 근거도 `E_low`개(초기값 5) 이하이면 부모로 합친다. 분리와 합치기의 문턱을 달리 둬 기준 근처에서 반복하지 않게 한다. 롤백 직후에는 바로 합치지 않고 다음 lint에서 본다.
   - 여러 부모에 걸친 항목 승격: 집 밖의 다른 부모 페이지 2곳 이상에서 참조되는 하위 항목(부모가 모두 3곳 이상)은 독립된 개념이다. 자기 페이지로 승격하고, 부모들에는 요약과 링크를 남긴다. 같은 항목이 분리 기준도 넘으면 승격을 먼저 한다. 집과 다른 부모 1곳만으로 승격하면 페이지 수가 다시 늘어 기각했다.
   - 집 이동: 다른 부모 쪽 근거가 훨씬 많아지면 집을 옮긴다.
   - 관계 후보 링크를 덧붙이던 일은 하지 않는다. 연결은 하위 항목 배정과 참조로 표현한다.
5. **클러스터는 남기되 문턱을 올린다.** 의미 클러스터(ADR-0037)는 그대로 쌓는다. 승격은 같은 대분류 아래 하위 분류가 `P`개(초기값 5) 이상 모인 클러스터만 한다. 근거 문서 2개 이상 조건(`MIN_PROMOTION_SOURCE_DOCUMENTS`)은 이 조건으로 바꾼다.
6. **분리·이동·승격은 모두 기록 재생 안의 작업이다.**
   - 분리는 lint 작업 하나로 부모·자식 양쪽에 기록한다. 부모에는 "이 항목들을 자식 페이지로 보냄", 자식에는 "이 항목들을 받음"을 남긴다.
   - 옮긴 항목의 원래 편입 기록은 원래 작업 id 그대로 자식 페이지에도 연결한다. 그래서 문서 X의 편입을 롤백하면 X의 기록이 붙은 부모·자식이 모두 다시 만들어진다. 재생의 "한 페이지 한 slug" 가정은 페이지 identity를 slug가 아닌 page id로 보도록 바꾼다.
   - 분리 롤백은 "자식을 부모로 병합"과 같게 처리한다. 자식 → 부모 방향 전환을 기록해 자식을 가리키던 링크와 본문 Related Concepts가 부모로 옮겨 간다(병합 대상 따라가기와 같은 처리). 방향 전환 없이 자식을 지우면 그 링크가 고아 간선으로 사라진다.
   - 분리 직후 부모를 가리키던 링크 중 실제로 그 하위 항목을 뜻하던 것은 고아가 아니다. 분리 작업에서 함께 옮기거나 다음 lint에서 바뀐 페이지만 다시 판정한다.
7. **임베딩은 하위 항목 단위로 만든다.**
   - `wiki_embedding_units`에 `sub_entry` 단위와 `entry_id`를 둔다. 하위 항목에 딸린 근거 단위(관찰·핵심 내용·원문 블록)에도 같은 `entry_id`를 붙인다. 검색은 페이지 전체가 아니라 하위 항목과 그 근거에 걸리므로 부모 페이지가 커져도 큰 청크 하나가 되지 않는다.
   - 페이지 임베딩(`wiki_page_embeddings`)은 정의와 하위 항목 목록을 나타내는 범위 요약으로 쓴다.
   - 표현 텍스트는 "바로 위 항목 이름 > 항목 이름 + 근거"다. 짧은 이름의 뜻을 정하려고 바로 위 이름을 붙이고, 전체 경로는 붙이지 않는다. 분리돼도 자식들의 바로 위는 그대로라 텍스트가 바뀌지 않고, 벡터는 표현 텍스트로 재사용되므로 분리는 단위의 `page_id`만 바꾼다. 새로 임베딩하는 것은 부모·자식 페이지 요약과 lint가 다른 상위 항목으로 옮긴 항목뿐이다.
   - 참조 항목은 벡터를 갖지 않는다. 같은 내용이 검색 결과에 중복으로 나오지 않게 한다.
   - 같은 것 찾기(3)는 이 `sub_entry` 벡터로 후보를 고른다(BGE-M3 0.75 + BM25 0.25, ADR-0038과 같다). 단위 생성은 2단계, 검색 단위의 최종 결정은 4단계 RAG 평가로 한다.
8. **프롬프트에 평가 원문 예시를 넣지 않는다.** 범위는 개수 규칙으로 잡는다. 크기 감을 보여 줄 예시가 필요하면 평가 원문에 없는 분야로 쓴다.
9. **기존 데이터는 이전하지 않는다.** 개발 단계라 ADR-0033처럼 위키 데이터를 비운 DB에 배포하고 다시 편입한다. 옛 개념 저장 경로와 대체된 lint 링크 승격 코드는 같은 변경에서 지운다.

**1단계 구현으로 정한 형식.** 기여 JSON과 조회용 사본의 정확한 형식은 [data-model](../data-model.md)에 둔다.
- 하위 항목의 추가·이동·삭제는 기여 JSON의 `entry_changes`(`add`·`move`·`remove`)다. 같은 항목을 여러 기여가 `add`하면 근거가 합쳐지고, 그 기여가 모두 빠져야 항목이 사라진다. 삭제는 그 아래 항목까지 지운다.
- 참조는 참조하는 페이지 기여의 `entry_reference` 링크이며 `entry_id`를 싣는다. 고아 판정은 지금처럼 페이지 쌍 단위다. 그래서 집 페이지가 남아 있고 다른 작업이 둔 참조만 있으면, 가리키던 항목이 빠져도 참조는 고아가 되지 않는다. 이 경우는 3단계 lint 재검사가 맡는다.
- 분리(6)는 lint 작업 하나가 부모(`remove`)와 자식(개념·`split_from`, 3단계 참고) 양쪽에 기록을 남기는 형식이다. 자식에 잇는 원래 편입 기록은 `concept` 없이 옮긴 항목의 `entry_changes`와 근거만 가진다. 재생은 slug가 아닌 page_id로 페이지를 묶는다.
- 워크스페이스 단위 이름 조회(3의 같은 것 찾기)는 ai DB `wiki_page_entries`를 쓴다. 복구 재생 결과로 다시 쓰는 파생 상태다. 1단계에서는 이 테이블을 복구만 썼고, 2단계부터 편입도 새 항목을 더한다.

**2단계 구현으로 정한 형식.**
- 배정 대상은 개념 판정(병합·연결)이 끝난 이번 문서의 개념이다. 기존 개념 페이지(이번 문서 개념이 병합된 것 포함)는 상위 항목만 된다. 기존 페이지를 다른 페이지 아래로 옮기는 일은 3단계 lint가 한다.
- 이름 규칙은 세부 항목 제목이 상위 항목 제목·별칭으로 시작하거나(단어 경계) `(상위 항목)` 수식어를 가지면 배정한다. 상위 후보는 이번 문서 개념과 워크스페이스 기존 개념이고, 가장 긴 이름이 이긴다. `part_of`는 이번 문서 개념끼리만 묻는다. 한 세부 항목에 part_of가 여럿이면 P(part_of)가 가장 높은 상위 항목에 두고, 서로가 서로에 딸린다는 판정은 버린다. 배정이 순환하면 버린다.
- 배정을 따라 올라간 맨 위 항목 아래 세부 항목 수(모든 깊이)로 `K`를 잰다. 맨 위 항목이 기존 페이지면 `K`와 무관하게 그 페이지에 둔다. 모자라면 배정을 모두 버리고 지금처럼 각자 개념 페이지로 둔다. 중간 상위 항목은 `K`를 넘어도 같은 페이지 안의 중첩 항목으로 두고, 분리는 3단계 lint가 한다.
- 세부 항목은 개념 목록에서 빠지고, 근거·연결(나가는 쪽과 받는 쪽 모두)·갱신 판정은 집 페이지를 가리킨다. 집은 위 항목부터 정한다. 위 항목이 다른 페이지의 기존 항목과 같으면 새 아래 항목도 그 페이지에 그 항목 아래로 둔다. 집 페이지나 참조를 두는 페이지가 이번 문서 개념에 없던 기존 페이지면 개념 판정이 기존 개념에 병합할 때와 같게 개념 목록에 넣는다. 그래야 그 페이지 기여에 참조가 남아 복구 재생이 된다.
- 같은 것 찾기는 "바로 위 이름 > 이름"이 같으면 판정 없이 같은 항목으로 보고, 나머지는 같음·관련 쌍 판정(`judge_concepts`)의 `same`만 같은 항목으로 본다. 후보는 지금 쌍 판정과 같이 정의 텍스트 BGE-M3 0.75 + BM25 0.25 상위 100개다. DB의 `sub_entry` 벡터로 후보를 고르는 일과 후보 수 상한은 4단계 검색 평가와 함께 정한다.
- 참조의 이름·위치는 `wiki_page_entry_references` 사본에 두고, 편입은 사본에 변경을 더한 뒤 본문 목록을 사본 전체로 다시 그린다. 복구 재생과 같은 목록이 나온다.
- `sub_entry` 표현 텍스트의 "근거"는 항목 정의로 쓴다. 근거 문장을 넣으면 근거가 늘 때마다 텍스트가 바뀌어 벡터를 다시 써야 한다. 근거 문장은 같은 `entry_id`를 가진 근거 단위가 맡는다.

**3단계 구현으로 정한 형식.** 정확한 형식은 [data-model](../data-model.md)에 둔다.
- 변경 표시(4)는 컬럼으로 두지 않고 작업 기록에서 정한다. 지난 성공 lint(`pipeline_runs`) 시작 뒤 갱신된 개념 페이지와 그 lint가 미룬 페이지(`deferred_entry_pages`), 그 페이지들의 기여가 더하거나 지운 참조의 집 페이지다. 비었어도 분리로 만든 자식은 다시 합치기 후보로 남긴다. 표시를 쓰고 지우는 곳(편입·복구·수동 편집·lint)을 모두 맞추지 않아도 되고, 롤백 직후 판단도 같은 기록(그 뒤 성공한 복구의 `changed_pages`)으로 한다. 갱신 시각은 하위 항목 외의 변경에도 바뀌어 더 보게 되지만 판정이 규칙이라 비용이 작다.
- 부모에 남기는 요약 줄은 `entry_reference`다(개념 링크가 아니다). 항목이 있던 자리에 자식 페이지 링크로 그려지고, 분리 기록과 함께 복원·고아 판정을 따른다.
- 분리는 옮긴 항목마다 `remove`를 남긴다. 뿌리 항목을 만든 편입을 되돌려도 다른 편입이 더한 아래 항목이 부모에 남지 않는다. 자식의 lint 기록에는 항목 변경을 두지 않는다. 항목과 근거는 원래 작업 id로 이은 편입 기록에서만 오므로, 그 편입을 되돌리면 자식에서도 빠진다.
- 다시 합치기는 새 연산 `revive`로 분리 때 지운 항목을 근거째 되살리고, 분리 뒤 자식에만 기여한 편입 기록을 부모에 잇는다. 기록이 페이지·작업마다 하나라 같은 작업이 분리 뒤 부모와 자식에 다 기여했으면 합치지 않는다. 한 lint에서 자식 여럿을 합치며 같은 작업을 부모에 여러 번 이으면 한 기록으로 합친다. 자식이 다른 페이지를 참조해도 합치지 않는다.
- 다시 합치기는 자식 페이지 자체에 쌓인 근거도 센다. 분리 뒤 자식에 쌓인 편입 기록은 항목 변경이 없어도 부모로 잇고, 사람이 고친 자식은 합치지 않는다.
- 다시 합치기는 되돌릴 수 있다. 자식에도 합친 기록(`merged_into`, 자식이 내던 링크 삭제, 다른 페이지에서 부모로 옮긴 간선 `redirected_links`)을 남긴다. 이은 기록에는 잇게 한 lint를 `linked_by_operation_id`로 표시한다. lint 복원은 대상 lint 기록과 그 lint가 이은 기록을 빼고 지운 자식을 재조립하며, 옮긴 간선을 자식으로 되돌린다. 부모 쪽 간선은 원래 페이지 기록이 그 뒤 직접 잇지 않을 때만 지우고, 자식 쪽 간선은 원래 페이지의 지금 기록이 아직 이을 때만 되살린다.
- 분리·승격은 위 항목부터 한다. 위 항목과 그 아래 항목이 둘 다 기준을 넘으면 위 항목만 옮기고 아래 항목은 새 페이지에서 다음 lint가 본다. 같은 lint에서 자식을 합쳐 받은 부모는 분리·승격하지 않고 다음 lint로 미룬다. 합치기 전 항목으로 나누면 되살린 항목이 새 페이지로 이어지지 않는다.
- 방향 전환(6)은 `wiki_pages.merged_into_page_id`다. 합칠 때(다시 합치기, 분리 롤백) 자식을 가리키던 링크를 부모로 옮기고, 그 뒤 지운 자식을 가리키는 기록을 재생해도 부모로 잇는다. MediaWiki가 병합한 문서 자리에 넘겨주기를 남기는 방식과 같다. 다른 페이지 본문의 `[[자식 slug]]` 글자는 고치지 않는다.
- 분리는 옮긴 항목 아래 둔 다른 페이지 참조도 새 페이지로 옮긴다. 옮길 항목을 모두 정한 뒤 참조를 최종 위치로 잇는다. 새 페이지 slug는 지운 페이지 slug까지 피한다. 지운 페이지 id를 다시 쓰면 옛 lint를 복원할 기록을 덮어쓴다. 쓰지 않게 된 벡터는 바뀐 페이지 단위를 모두 쓴 뒤 지워 옮긴 항목의 벡터를 그대로 쓴다(7).
- 여러 부모 승격은 분리와 같은 연산이다. 집 밖 참조 부모 페이지 2곳 이상인 항목을 자기 페이지로 옮기고, 참조하던 페이지의 참조 대상을 새 페이지로 바꾼다.
- 같은 페이지 안 하위 항목 이동·합치기(판정 필요)와 집 이동은 이번 단계에 넣지 않았다.
- 이 형식은 document-svc 기여 원장이 lint 결과의 `ledger_contributions`를 페이지별 행으로 기록하고, `deleted_pages`의 기여를 비활성으로 바꾸고, lint 복원 때 대상 lint 기록과 그 lint가 이은 기록(`linked_by_operation_id`)을 빼고 그 lint가 지운 페이지의 기여를 다시 활성으로 돌려 재조립해야 동작한다. document-svc 쪽 변경은 따로 진행 중이다.

`K`, `C`, `C_low`, `E`, `E_low`, `P`와 `PART_OF_MIN_PROBABILITY`는 초기값이다. 아래 계획 0단계의 지표로 정한다.

## Alternatives
- **대분류 목록을 미리 정의하고 그 안으로만 분류**: 범위는 가장 안정적이다. 하지만 워크스페이스·분야마다 목록을 관리해야 하고, 목록에 없는 주제가 들어오면 갈 곳이 없다. 기각.
- **프롬프트에 크기 예시를 주고 모델이 대분류를 고르게 하기**: 가장 간단하다. 하지만 크기 판단을 여전히 모델에 맡겨 모델마다 결과가 다르다는 원래 문제가 남는다. 예시가 평가 원문 분야면 점수도 부풀린다. 단독으로는 기각하고, 개수 규칙의 보조로만 쓴다.
- **세부 항목을 지금처럼 개념 페이지로 두고 상하위 링크만 더하기**: 저장 구조를 바꾸지 않는다. 하지만 페이지 수와 링크 수가 그대로라 그래프가 엉키는 문제가 그대로다. 기각.
- **같은 하위 항목을 페이지마다 복사**: 구현이 쉽다. 하지만 같은 내용이 여러 곳에서 따로 바뀌어 어긋나고 검색에서 중복된다. 기각.
- **분리를 페이지 본문만 고치는 방식으로 하기**: 기록 재생과 맞지 않아 롤백과 고아 간선 판정이 모두 깨진다. 기각.
- **lint 때 워크스페이스 전체를 다시 배정**: 정확하지만 비용이 문서 수에 비례해 커진다. 바뀐 페이지만 보는 방식으로 기각.

## Consequences
- 개념 페이지 수가 줄고 페이지마다 하위 항목 인덱스가 생긴다. 같은 문서를 다른 모델로 편입해도 개념 페이지 수가 비슷해질 것으로 기대한다. 0단계 지표로 확인한다.
- 편입 반영 단계의 판정이 늘어(배정·같은 것 찾기) 잠금을 쥐는 시간이 길어진다. 이름 규칙으로 판정 없이 처리하는 비율과 후보 수 상한으로 줄인다.
- lint 비용은 바뀐 페이지 수에 비례한다.
- 검색 단위(부모 페이지에 자식 내용을 넣을지, 하위 항목을 따로 색인할지)는 4단계에서 RAG 평가로 정한다.
- 단계별로 쌓아 배포한다. 각 단계는 앞 단계 위에서 따로 동작하고, 단계마다 검증 기준을 둔다.

| 단계 | 내용 | 검증 |
|---|---|---|
| 0. 측정 기준 | 같은 문서 11개를 모델 2~3개로 편입해 개념 페이지 수 편차와 대분류 일치율을 잰다. 하위 항목 쌍 정답 세트(같음/맥락 다름/무관, `part_of`)를 만들어 `gold.lock.json`에 고정한다 | 현재 편차가 수치로 남는다(지금 관찰: Deployment·kubectl 개념 2~17개) |
| 1. 저장 구조 | 하위 항목 id·`parent_entry_id`·집·참조, 기여 기록 형식, 재생과 본문 렌더링. 판정 없이 지금 개념을 하위 항목 없는 페이지로 그대로 재생 | 기존 편입·복원·고아 간선 테스트가 그대로 통과한다. 하위 항목 추가·이동·삭제 재생 테스트 |
| 2. 편입 배정과 승격 | 이름 규칙 배정, `part_of` 쌍 판정, 같은 것 찾기와 참조, `K` 기반 승격 | 0단계 지표에서 모델 간 개념 수 편차 감소, 하위 항목 쌍 판정 정답률. RAG 정답·주장 대조가 기준선보다 나빠지지 않는다 |
| 3. lint 재검사·분리 | 변경 표시, 이동·합치기·분리·다시 합치기, 분리 기록과 자식 → 부모 방향 전환 롤백 | 분리 뒤 편입 롤백·lint 롤백에서 부모·자식 페이지와 링크가 분리 전 상태로 돌아간다. 고아 간선이 남지 않는다 |
| 4. 승격 규칙 교체와 검색 | 여러 부모 참조 승격, 클러스터 `P` 조건, lint 관계 후보 링크 생성 삭제, 검색 단위 결정 | lint 관계 후보 수 감소(지금 44), 승격 페이지의 문서 연결 누락 0, RAG 평가로 검색 단위 결정 |

- 이 결정이 Accepted가 되면 ADR-0037(승격 조건, lint 링크 승격)과 ADR-0038(lint 승격 링크)의 해당 부분을 개정한다.
