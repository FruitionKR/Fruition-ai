# 0042. 개념 페이지는 하위 항목을 모아 두는 대분류로 만들고, 두꺼워진 하위 항목은 자식 페이지로 분리한다

## Status
Proposed

## Context
- **개념 크기가 모델 판단에 달려 있다.** 편입 추출 모델이 정하는 개념 크기가 곧 개념 페이지 크기다. 같은 Kubernetes 문서를 넣었는데도 이름에 Deployment·kubectl이 들어간 개념 페이지 수가 워크스페이스마다 2~17개로 달랐다(로컬 평가 워크스페이스 10곳, 2026-11-01).
  - 최근 워크스페이스에는 `Deployment Rollout`, `Deployment Rollback`, `Deployment Conditions`, `Label Selector (Deployment)`, `kubectl scale`, `kubectl rollout history`, `디플로이먼트 재생성`이 각각 개념 페이지로 생겼다. 모두 Deployment 페이지 안의 항목이면 충분한 크기다.
  - 개념 판정(ADR-0038)은 같은 개념을 합치고 직접 관계만 잇는다. "B가 A에 딸린 세부 내용"이라는 판정은 없다. 그래서 세부 항목은 별도 개념으로 남거나 링크로 이어질 뿐이다.
- **lint가 구조가 아니라 링크를 덧붙인다.** lint 승격(ADR-0037)은 근거 문서 2개 이상인 클러스터를 개념 페이지로 만들고 기존 개념과 쌍 판정해 링크를 잇는다. 11개 문서 평가에서 관계 후보가 44개 올라왔고, 일부 승격 페이지는 문서 연결(`document_wiki_links`)이 없었다. 잘게 쪼개진 개념을 링크로 보완할수록 그래프가 엉킨다.
- **크게 잡기만 하면 RAG 문제가 돌아온다.** 개념 페이지가 커지면 페이지 하나가 큰 청크가 되어 검색과 근거 선택의 정밀도가 떨어진다.
- **기존 저장·복원 구조.** 개념 페이지는 작업마다 남긴 기여 기록(`wiki/{workspace_id}/pages/{page_id}/ops/{operation_id}.json`)을 순서대로 재생해 만든다(`concept_contribution_rebuild.py`). 링크도 기록의 추가·삭제를 재생해 정한다(`replay_supported_links`). 편입·lint 복원은 취소한 작업의 기록을 빼고 재생한다. 고아 간선은 끝 페이지가 지워졌거나(`endpoint_deleted`) 재생한 기록에 근거가 없는(`no_active_support`) 링크다. 재생은 한 페이지의 생성 기록이 모두 같은 slug라고 가정한다.

## Decision
위키백과의 요약식 문서(Summary style)와 B-tree 노드 분할을 따른다. 내용은 모이면 올라가고 두꺼워지면 쪼개진다. 크기는 모델의 감각이 아니라 **모인 개수와 근거량**으로 정한다.

1. **하위 항목을 데이터로 둔다.**
   - 개념 페이지는 하위 항목(sub-entry) 목록을 가진다. 하위 항목은 워크스페이스 안에서 고정 id, 이름, 근거, 상위 항목(`parent_entry_id`, 없으면 페이지 바로 아래)을 가진다.
   - 본문의 하위 항목 목록(인덱스)은 이 데이터로 그린다. 중첩 목록으로 렌더링한다.
   - 하위 항목의 추가·이동·삭제는 기여 기록에 id로 남긴다. 페이지와 하위 항목은 모두 기록 재생으로 만든다.
2. **하위 항목의 집은 하나, 다른 페이지에는 참조만 둔다.**
   - 하위 항목은 한 페이지(집)에만 속한다. 다른 페이지에 같은 것이 나오면 내용을 복사하지 않고 그 항목을 가리키는 참조 항목을 둔다.
   - 소유 관계는 트리다. 참조는 링크로 저장해 고아 간선 규칙을 그대로 따른다.
3. **편입: 세부 항목을 뽑고, 상위 항목에 배정하고, 개수로 승격한다.**
   - 추출은 지금처럼 세부 항목까지 뽑는다. 잘게 뽑혀도 된다.
   - 배정: 세부 항목마다 이번 문서의 핵심 항목 중 어디에 딸리는지 정한다. 이름이 상위 항목 이름으로 시작하거나 그 이름을 수식어로 가지면 판정 없이 배정한다. 나머지는 Jev 쌍 판정에 `part_of`(B는 A에 딸린 세부 내용)를 더해 묻는다. 확신이 낮으면 배정하지 않는다.
   - 같은 것 찾기: 새 세부 항목은 워크스페이스의 기존 하위 항목에서 이름·임베딩 상위 후보 몇 개만 골라 쌍 판정한다. `same`이면 기존 항목에 근거를 더하고 이번 부모에는 참조를 둔다. 맥락이 다르면(같은 이름의 다른 동작·설정) 이번 부모 아래 새 항목으로 둔다. **애매하면 따로 둔다.** 다른 것을 같은 것으로 합치는 오류가 반대 오류보다 해롭고, 따로 둔 중복은 lint 재검사로 고칠 수 있다.
   - 승격: 세부 항목이 `K`개 이상 배정된 항목만 개념 페이지가 된다. 모자라면 가장 가까운 상위 페이지의 하위 항목으로 들어간다.
   - 판정은 ADR-0033대로 편입 반영 단계(워크스페이스 개념 잠금 안)에서 한다.
4. **lint: 바뀐 페이지만 재검사하고, 분리·이동·합치기를 한다.**
   - 이번에 하위 항목이 바뀐 페이지에 변경 표시를 하고, lint는 그 페이지만 본다. 판정 범위는 그 페이지의 하위 항목이다. 비용은 워크스페이스 크기가 아니라 변경량에 비례한다.
   - 이동: 잘못 배정된 하위 항목을 다른 상위 항목으로 옮긴다. 하위의 하위가 맞으면 그 아래로 넣는다.
   - 합치기: 같은 내용의 하위 항목을 하나로 합친다.
   - 분리: 하위 항목의 자식이 `C`개(초기값 5) 이상이거나, 근거가 `E`개 이상이거나 근거 원문 문서가 2개 이상이면 자식 페이지로 분리한다. 부모에는 요약과 자식 페이지 링크를 남긴다. 상위 항목 값만 바꾸므로 그 아래 자식들은 함께 내려간다. 분리 규칙이 있어 한 페이지 안의 하위 항목 깊이는 2단계 정도에서 멈추고, 깊어지는 것은 페이지 트리다.
   - 다시 합치기: 자식 페이지가 줄어 자식 `C_low`개(초기값 2) 이하이고 근거도 기준 아래로 내려가면 부모로 합친다. 분리와 합치기의 문턱을 달리 둬 기준 근처에서 반복하지 않게 한다. 롤백 직후에는 바로 합치지 않고 다음 lint에서 본다.
   - 여러 부모에 걸친 항목 승격: 참조가 2개 이상 부모에 걸린 하위 항목은 독립된 개념이다. 자기 페이지로 승격하고, 부모들에는 요약과 링크를 남긴다.
   - 집 이동: 다른 부모 쪽 근거가 훨씬 많아지면 집을 옮긴다.
   - 관계 후보 링크를 덧붙이던 일은 하지 않는다. 연결은 하위 항목 배정과 참조로 표현한다.
5. **클러스터는 남기되 문턱을 올린다.** 의미 클러스터(ADR-0037)는 그대로 쌓는다. 승격은 같은 대분류 아래 하위 분류가 `P`개(초기값 5) 이상 모인 클러스터만 한다. 근거 문서 2개 이상 조건(`MIN_PROMOTION_SOURCE_DOCUMENTS`)은 이 조건으로 바꾼다.
6. **분리·이동·승격은 모두 기록 재생 안의 작업이다.**
   - 분리는 lint 작업 하나로 부모·자식 양쪽에 기록한다. 부모에는 "이 항목들을 자식 페이지로 보냄", 자식에는 "이 항목들을 받음"을 남긴다.
   - 옮긴 항목의 원래 편입 기록은 원래 작업 id 그대로 자식 페이지에도 연결한다. 그래서 문서 X의 편입을 롤백하면 X의 기록이 붙은 부모·자식이 모두 다시 만들어진다. 재생의 "한 페이지 한 slug" 가정은 페이지 identity를 slug가 아닌 page id로 보도록 바꾼다.
   - 분리 롤백은 "자식을 부모로 병합"과 같게 처리한다. 자식 → 부모 방향 전환을 기록해 자식을 가리키던 링크와 본문 Related Concepts가 부모로 옮겨 간다(병합 대상 따라가기와 같은 처리). 방향 전환 없이 자식을 지우면 그 링크가 고아 간선으로 사라진다.
   - 분리 직후 부모를 가리키던 링크 중 실제로 그 하위 항목을 뜻하던 것은 고아가 아니다. 분리 작업에서 함께 옮기거나 다음 lint에서 바뀐 페이지만 다시 판정한다.
7. **프롬프트에 평가 원문 예시를 넣지 않는다.** 범위는 개수 규칙으로 잡는다. 크기 감을 보여 줄 예시가 필요하면 평가 원문에 없는 분야로 쓴다.
8. **기존 데이터는 이전하지 않는다.** 개발 단계라 ADR-0033처럼 위키 데이터를 비운 DB에 배포하고 다시 편입한다. 옛 개념 저장 경로와 대체된 lint 링크 승격 코드는 같은 변경에서 지운다.

`K`, `C`, `C_low`, `E`, `P`는 초기값이다. 아래 계획 0단계의 지표로 정한다.

## Alternatives
- **대분류 목록을 미리 정의하고 그 안으로만 분류**: 범위는 가장 안정적이다. 하지만 워크스페이스·분야마다 목록을 관리해야 하고, 목록에 없는 주제가 들어오면 갈 곳이 없다. 기각.
- **프롬프트에 크기 예시를 주고 모델이 대분류를 고르게 하기**: 가장 간단하다. 하지만 크기 판단을 여전히 모델에 맡겨 모델마다 결과가 다르다는 원래 문제가 남는다. 예시가 평가 원문 분야면 점수도 부풀린다. 단독으로는 기각하고, 개수 규칙의 보조로만 쓴다.
- **세부 항목을 지금처럼 개념 페이지로 두고 상하위 링크만 더하기**: 저장 구조를 바꾸지 않는다. 하지만 페이지 수와 링크 수가 그대로라 그래프가 엉키는 문제가 그대로다. 기각.
- **같은 하위 항목을 페이지마다 복사**: 구현이 쉽다. 하지만 같은 내용이 여러 곳에서 따로 바뀌어 어긋나고 검색에서 중복된다. 기각.
- **분리를 페이지 본문만 고치는 방식으로 하기**: 기록 재생과 맞지 않아 롤백과 고아 간선 판정이 모두 깨진다. 기각.
- **lint 때 워크스페이스 전체를 다시 배정**: 정확하지만 비용이 문서 수에 비례해 커진다. 바뀐 페이지만 보는 방식으로 기각.

## Consequences
- 개념 페이지 수가 줄고 페이지마다 하위 항목 인덱스가 생긴다. 같은 문서를 다른 모델로 편입해도 개념 페이지 수가 비슷해질 것으로 기대한다. 0단계 지표로 확인한다.
- 편입 반영 단계의 판정이 늘어(배정·같은 것 찾기) 잠금을 쥐는 시간이 길어진다. 이름 규칙으로 판정 없이 처리하는 비율과 후보 수 상한으로 줄인다.
- lint 비용은 바뀐 페이지 수에 비례한다.
- 검색 단위(부모 페이지에 자식 내용을 넣을지, 하위 항목을 따로 색인할지)는 4단계에서 RAG 평가로 정한다.
- 단계별로 쌓아 배포한다. 각 단계는 앞 단계 위에서 따로 동작하고, 단계마다 검증 기준을 둔다.

| 단계 | 내용 | 검증 |
|---|---|---|
| 0. 측정 기준 | 같은 문서 11개를 모델 2~3개로 편입해 개념 페이지 수 편차와 대분류 일치율을 잰다. 하위 항목 쌍 정답 세트(같음/맥락 다름/무관, `part_of`)를 만들어 `gold.lock.json`에 고정한다 | 현재 편차가 수치로 남는다(지금 관찰: Deployment·kubectl 개념 2~17개) |
| 1. 저장 구조 | 하위 항목 id·`parent_entry_id`·집·참조, 기여 기록 형식, 재생과 본문 렌더링. 판정 없이 지금 개념을 하위 항목 없는 페이지로 그대로 재생 | 기존 편입·복원·고아 간선 테스트가 그대로 통과한다. 하위 항목 추가·이동·삭제 재생 테스트 |
| 2. 편입 배정과 승격 | 이름 규칙 배정, `part_of` 쌍 판정, 같은 것 찾기와 참조, `K` 기반 승격 | 0단계 지표에서 모델 간 개념 수 편차 감소, 하위 항목 쌍 판정 정답률. RAG 정답·주장 대조가 기준선보다 나빠지지 않는다 |
| 3. lint 재검사·분리 | 변경 표시, 이동·합치기·분리·다시 합치기, 분리 기록과 자식 → 부모 방향 전환 롤백 | 분리 뒤 편입 롤백·lint 롤백에서 부모·자식 페이지와 링크가 분리 전 상태로 돌아간다. 고아 간선이 남지 않는다 |
| 4. 승격 규칙 교체와 검색 | 여러 부모 참조 승격, 클러스터 `P` 조건, lint 관계 후보 링크 생성 삭제, 검색 단위 결정 | lint 관계 후보 수 감소(지금 44), 승격 페이지의 문서 연결 누락 0, RAG 평가로 검색 단위 결정 |

- 이 결정이 Accepted가 되면 ADR-0037(승격 조건, lint 링크 승격)과 ADR-0038(lint 승격 링크)의 해당 부분을 개정한다.
