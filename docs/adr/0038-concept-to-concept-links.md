# 0038. 개념끼리의 그래프 링크는 판단을 거친 관계만 만든다

## Status
Accepted

## Context
질의는 시드 페이지에서 `wiki_page_links`를 따라 그래프를 탐색해 근거를 모은다(`TRAVERSABLE_RELATION_TYPES`). 그래서 개념끼리 링크가 없으면, 관련 개념이 있어도 탐색이 그쪽으로 넘어가지 못한다.

- 2026-07-02 이전 편입은 같은 근거에 함께 나옴, 핵심 내용 공유, 병합 판단의 연결 대상, 힌트 판정, 페이지 생성 시 LLM이 지목한 관련 개념을 모두 `concept_related_to`로 만들었다. 약한 관계까지 링크가 돼 그래프가 시끄러웠다.
- 2026-07-02(local-pilot `3644e42f`)에 편입 시점의 개념 간 링크를 모두 지웠다. 관계는 lint가 판정해 종류 있는 링크(`part_of`, `uses_or_depends_on` 등)로 만들게 했다. 이때 판단을 거친 관계도 같이 빠졌다.
- lint는 클러스터 후보와 개념 사이의 관계만 만든다. 이미 있는 개념끼리는 다루지 않는다. 같은 문서의 개념은 source 페이지를 거쳐 두 단계로 이어지지만, 다른 문서의 기존 개념과 관련된 새 개념은 어디에도 이어지지 않는다.
- 2026-08-20 품질 재평가 보고서는 이 공백을 "검증된 관계의 그래프 링크 공백"으로 적고, 링크로 저장할지는 제품 계약을 먼저 정하라고 보류했다.
- 사용자가 본문 `[[slug]]`로 만든 개념 간 링크(`related_to`, ADR-0031)도 탐색 대상이 아니었다.

## Decision
- 개념 병합 판단(`concept_resolution`, Jev 판정 포함)은 새 개념마다 같은 개념으로 병합(`merge_into`), 따로 두고 연결(`link_to`), 따로 둠 중 하나를 정한다. `link_to`는 뜻이 다르지만 상하위·일부·단계·방법·변형·같은 상위 개념 아래의 형제·직접 의존처럼 분명히 관련된 경우다. 같은 분야이거나 같은 문서에 나왔다는 것만으로는 고르지 않는다. `link_to`는 관련 개념 여러 개(`link_targets`)와 이을 수 있다.
- Jev 판정(2026-10-29)은 후보와 한 쌍씩 묻는다.
  - 후보: 다른 incoming 개념과 기존 개념 중 정의가 있는 것을 제목·별칭·태그·정의로 하이브리드 점수(BGE-M3 0.75 + BM25 0.25)를 매겨 상위 100개를 고른다.
  - 이름 일치: 새 개념의 제목이나 별칭이 후보의 slug·제목·별칭과 slug로 같으면 Jev 없이 그 후보로 병합한다. 여러 개면 slug가 가장 앞인 후보다.
  - 쌍 판정: 후보마다 질문 하나로 `same`(동의어·번역·약어·표기 변형), `related`(위의 `link_to` 관계), `unrelated`(무관하거나 같은 분야·같은 문서일 뿐) 중 하나를 고른다. 판정 규칙은 질문마다 반복하지 않도록 요청 state에 한 번만 두고, 질문에는 판정할 후보 ID만 적는다. 질문마다 규칙을 두는 방식과 정확도가 같은지는 Jev on/off 평가 전까지 확인하지 않았다.
  - 결정: `same`으로 고른 후보가 있으면 P(same)이 가장 높은 후보로 병합한다. 없고 `related`로 고른 후보가 있으면 그 후보 모두와 P(related) 높은 순으로 연결하고, 링크 확신도는 대상별 P(related)(`link_confidences`)다. 둘 다 없으면 새 개념으로 둔다. 병합 대상이 다시 병합되는 연쇄는 버린다.
- `LinkBuilder`는 `link_to` 판정에서만 개념끼리의 `concept_related_to` 링크를 만든다. 링크 확신도는 대상별 확신도가 있으면 그것을, 없으면 판정 전체 확신도를 쓴다. 대상은 같은 편입의 개념이거나 다른 문서의 기존 개념이다. 대상이 같은 편입에서 병합되면 병합된 개념으로 잇는다.
- lint 승격(ADR-0037)도 생성한 개념 페이지를 기존 개념과 같은 쌍 판정으로 묻고, `link_to`이면 새 개념에서 대상마다 `concept_related_to` 링크를 대상별 확신도로 만든다. 이 링크는 lint 기록(`materialized_relations` → operation artifact `added_links`)에 남아 lint 복원 시 지운다.
- 함께 나옴·핵심 내용 공유처럼 판단을 거치지 않은 관계는 지금처럼 본문 Related Concepts에만 적고 링크로 만들지 않는다.
- 힌트 판정(`hint_resolutions`)은 링크를 만들지 않는다. 힌트는 페이지가 없는 표기라, `related_only`도 힌트의 근거를 대상 개념에 붙일 뿐 이을 개념 쌍이 없다.
- 사용자가 직접 만든 `related_to`도 그래프 탐색 대상에 넣는다.
- 상하위 같은 관계의 종류는 링크에 담지 않는다. 종류 있는 관계는 지금처럼 lint가 만든다.

## Alternatives
- **7월 이전처럼 함께 나옴·핵심 내용 공유도 링크로 만들기**: 그래프가 다시 시끄러워지고, 탐색이 관련 없는 개념으로 퍼진다.
- **lint가 기존 개념끼리의 관계도 판정하기**: 사용자가 lint를 돌려야만 링크가 생기고, 개념 쌍이 늘수록 판정 비용이 커진다. 병합 판단은 이미 새 개념과 기존 개념을 나란히 보고 있어 추가 호출 없이 정할 수 있다.
- **`link_to`에 상하위 같은 관계 종류까지 고르게 하기**: 그래프 탐색에는 종류가 필요 없고, 판단만 어려워진다.
- **선택지 하나에 후보 조합 담기(이전 방식: 후보 3개마다 병합·연결 + `keep_new` 중 하나 고르기)**: 후보 하나에 결과 하나만 고를 수 있어 관련 개념 여러 개와 잇지 못한다. 여러 후보의 조합을 선택지로 만들면 후보 수에 따라 선택지가 폭발하고, 비슷한 선택지끼리 확률이 나뉘어 확률을 확신도로 쓸 수 없다.
- **확률 문턱값으로 병합·연결 정하기**: 문턱값을 정할 튜닝 데이터가 아직 없다. 지금은 Jev가 고른 선택을 그대로 따르고 확률은 후보 사이 순위와 링크 확신도에만 쓴다.
- **형제 개념은 연결하지 않기**: 형제끼리 링크하면 상위 개념과 삼각형 순환이 생긴다. 하지만 탐색은 경로에 이미 있는 노드를 다시 방문하지 않고 깊이 한도도 있어 순환이 문제되지 않는다. 연결하지 않으면 형제 개념(같은 분류의 다른 현상·리소스)으로 탐색이 이어지지 않는다.

## Consequences
- 다른 문서의 관련 개념으로 그래프 탐색이 이어진다.
- 개념 하나에 후보 수만큼 질문을 보내 Jev 요청 수·비용이 이전보다 크다(후보 100개면 요청 약 3개).
- 병합 판단이 `link_to`를 고르는 만큼 개념 간 링크가 늘어난다. 너무 넓게 고르면 탐색이 퍼지므로, 평가셋의 '따로 두고 연결' 사례로 정밀도를 확인한다.
- 이미 있는 개념끼리, 그리고 이번 변경 전에 편입된 개념에는 링크가 생기지 않는다. 다시 편입하거나 lint 판정으로만 이어진다.
- lint로 승격한 개념도 관련된 기존 개념과 이어진다.
