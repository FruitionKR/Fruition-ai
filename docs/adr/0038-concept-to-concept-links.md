# 0038. 개념끼리의 그래프 링크는 판단을 거친 관계만 만든다

## Status
Accepted

## Context
질의는 시드 페이지에서 `wiki_page_links`를 따라 그래프를 탐색해 근거를 모은다(`TRAVERSABLE_RELATION_TYPES`). 그래서 개념끼리 링크가 없으면, 관련 개념이 있어도 탐색이 그쪽으로 넘어가지 못한다.

- 2026-07-02 이전 편입은 같은 근거에 함께 나옴, 핵심 내용 공유, 병합 판단의 연결 대상, 힌트 판정, 페이지 생성 시 LLM이 지목한 관련 개념을 모두 `concept_related_to`로 만들었다. 약한 관계까지 링크가 돼 그래프가 시끄러웠다.
- 2026-07-02(local-pilot `3644e42f`)에 편입 시점의 개념 간 링크를 모두 지웠다. 관계는 lint가 판정해 종류 있는 링크(`part_of`, `uses_or_depends_on` 등)로 만들게 했다. 이때 판단을 거친 관계도 같이 빠졌다.
- lint는 클러스터 후보와 개념 사이의 관계만 만든다. 이미 있는 개념끼리는 다루지 않는다. 같은 문서의 개념은 source 페이지를 거쳐 두 단계로 이어지지만, 다른 문서의 기존 개념과 관련된 새 개념은 어디에도 이어지지 않는다.
- 2026-08-20 품질 재평가 보고서는 이 공백을 "검증된 관계의 그래프 링크 공백"으로 적고, 링크로 저장할지는 제품 계약을 먼저 정하라고 보류했다.
- 사용자가 본문 `[[slug]]`로 만든 개념 간 링크(`related_to`, ADR-0031)도 탐색 대상이 아니었다.

## Decision
- 개념 병합 판단(`concept_resolution`, Jev 판정 포함)은 새 개념마다 같은 개념으로 병합(`merge_into`), 따로 두고 연결(`link_to`), 따로 둠 중 하나를 고른다. `link_to`는 뜻이 다르지만 상하위·일부·단계·방법·변형·직접 의존처럼 분명히 관련된 경우다. 같은 분야이거나 같은 문서에 나왔다는 것만으로는 고르지 않는다.
- `LinkBuilder`는 `link_to` 판정에서만 개념끼리의 `concept_related_to` 링크를 만든다. 대상은 같은 편입의 개념이거나 다른 문서의 기존 개념이다. 대상이 같은 편입에서 병합되면 병합된 개념으로 잇는다.
- 함께 나옴·핵심 내용 공유처럼 판단을 거치지 않은 관계는 지금처럼 본문 Related Concepts에만 적고 링크로 만들지 않는다.
- 힌트 판정(`hint_resolutions`)은 링크를 만들지 않는다. 힌트는 페이지가 없는 표기라, `related_only`도 힌트의 근거를 대상 개념에 붙일 뿐 이을 개념 쌍이 없다.
- 사용자가 직접 만든 `related_to`도 그래프 탐색 대상에 넣는다.
- 상하위 같은 관계의 종류는 링크에 담지 않는다. 종류 있는 관계는 지금처럼 lint가 만든다.

## Alternatives
- **7월 이전처럼 함께 나옴·핵심 내용 공유도 링크로 만들기**: 그래프가 다시 시끄러워지고, 탐색이 관련 없는 개념으로 퍼진다.
- **lint가 기존 개념끼리의 관계도 판정하기**: 사용자가 lint를 돌려야만 링크가 생기고, 개념 쌍이 늘수록 판정 비용이 커진다. 병합 판단은 이미 새 개념과 기존 개념을 나란히 보고 있어 추가 호출 없이 정할 수 있다.
- **`link_to`에 상하위 같은 관계 종류까지 고르게 하기**: 그래프 탐색에는 종류가 필요 없고, 판단만 어려워진다.

## Consequences
- 다른 문서의 관련 개념으로 그래프 탐색이 이어진다.
- 병합 판단이 `link_to`를 고르는 만큼 개념 간 링크가 늘어난다. 너무 넓게 고르면 탐색이 퍼지므로, 평가셋의 '따로 두고 연결' 사례로 정밀도를 확인한다.
- 이미 있는 개념끼리, 그리고 이번 변경 전에 편입된 개념에는 링크가 생기지 않는다. 다시 편입하거나 lint 판정으로만 이어진다.
